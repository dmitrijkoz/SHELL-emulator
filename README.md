# Конфигурационное управление. Вариант №10, этап 2

## 1. Общее описание

Эмулятор shell для UNIX-подобной ОС. На втором этапе реализована конфигурация запуска:
путь к физическому VFS и путь к стартовому скрипту передаются через параметры командной
строки. При старте эмулятор выводит все полученные параметры, проверяет их и выполняет
стартовый скрипт до первой ошибки.

Стартовый скрипт отображается на экране как пользовательский ввод: каждая выполняемая
команда выводится с приглашением, после чего показывается результат её выполнения.

## 2. Параметры командной строки

Формат запуска:

```text
python -m src.shell_emulator <vfs_path> <startup_script>
```

где:

1. `<vfs_path>` — путь к физическому каталогу, который используется как корень VFS;
2. `<startup_script>` — путь к текстовому стартовому скрипту с командами эмулятора.

Пример:

```bash
py -m src.shell_emulator ./vfs ./scripts/startup_success.txt
```

При запуске выводится отладочная информация:

```text
Отладочная информация конфигурации:
  Путь к VFS: ...
  Путь к стартовому скрипту: ...
```

## 3. Стартовый скрипт

Скрипт выполняется последовательно до команды `exit` или до первой ошибки. При ошибке
выводится сообщение с номером строки и выполнение скрипта прекращается.

Пустые строки и строки, начинающиеся с `#`, считаются комментариями и не выполняются.

Поддерживаемые на этапе 2 команды:

- `ls` — вывод содержимого текущего каталога VFS;
- `cd` — переход внутри VFS;
- `exit` — завершение стартового скрипта и переход в интерактивный режим.

## 4. Тестовые сценарии

В каталоге `scripts/` находятся тестовые стартовые скрипты и скрипты реальной ОС,
которые запускают эмулятор с обоими параметрами командной строки:

```text
scripts/
├── run_stage2_success.bat
├── run_stage2_error.bat
├── run_stage2_quotes.bat
├── startup_success.txt
├── startup_error.txt
└── startup_quotes.txt
```

Для Windows:

```bat
scripts\run_stage2_success.bat
scripts\run_stage2_error.bat
scripts\run_stage2_quotes.bat
```

Сценарий `startup_error.txt` специально содержит ошибочную команду `cd missing-directory`.
По требованиям этапа 2 эмулятор после неё не выполняет следующие команды из скрипта.

## 5. Сборка и тесты

### Вручную

```bash
py -m unittest discover -s tests -v
```

## 6. Коды завершения

- `0` — успешное выполнение стартового скрипта;
- `1` — ошибка во время выполнения стартового скрипта;
- `2` — ошибка параметров или конфигурации запуска.
